SLIDE 2 — Architecture          [0:40]  (cum 1:00)   Yankai
-----------------------------------------------------------
Here is the design. On the left: four parties, each with a wallet and an on-chain role. In the middle: two contracts on Sepolia. BatchRegistry handles register, transfer, verify, and recall. ColdChainMonitor receives temperature data. If a reading is outside two to eight degrees, it quarantines the batch by itself, with a cross-contract call. Only this contract can do that — no person can. On the right: the off-chain parts. The oracle service reads the sensors and sends signed data. The store keeps metadata and patient data off-chain. The rule is simple: state goes on-chain; private data stays off-chain; only hashes connect them.
【中文】这是我们的设计。左边：四个参与方，每个都有一个钱包和一个链上角色。中间：Sepolia 上的两个合约。BatchRegistry 负责登记、转移、核验、召回。ColdChainMonitor 接收温度数据；如果读数超出 2 到 8 度，它会通过一次跨合约调用自动隔离该批次——而且只有这个合约能做，任何人都不能。右边：链下部分。预言机服务读取传感器并发送签名后的数据；存储把元数据和患者数据都放在链下。规则很简单：状态上链，隐私数据留在链下，只用哈希把两者连起来。

SLIDE 3 — Changes after feedback [0:40]  (cum 1:40)   Purui
-----------------------------------------------------------
Four changes since Task 2. First, the platform. Task 2 chose Fabric. We kept the same idea — only known, approved parties can write — but we now enforce it with roles inside the contract, on public Ethereum. So anyone can check our system on Etherscan, and we have real contract addresses. Second, we hardened the oracle: one authorised account, and the contract checks every reading. Third, non-repudiation is now real: every write is a signed transaction, so we always know who did what. Fourth, clear scope: the three MUSTs and the SHOULD are fully on-chain; the IoT part is simulated. In production we would move to a consortium chain — the contracts would not change.
【中文】相比 Task 2 有四处改动。第一，平台。Task 2 选了 Fabric。我们保留了同一个理念——只有已知的、获批的参与方才能写入——但现在改用合约内部的角色来强制实现，跑在公有以太坊上。所以任何人都能在 Etherscan 上核查我们的系统，我们也有了真实的合约地址。第二，我们加固了预言机：只有一个授权账户，且合约会校验每一条读数。第三，不可抵赖现在是实打实的：每次写入都是一笔签名交易，所以我们始终知道谁做了什么。第四，范围清晰：三个 MUST 和那个 SHOULD 完全上链；物联网部分是模拟的。生产环境我们会换成联盟链——合约本身不用改。

STEP 2 · Register  [0:55]  (cum 4:10)
  > $env:BATCH_ID = "PHX-LIVE-01"          (use a batch id never used before)

Three things, in order. One: the metadata went to an off-chain file — there is the path. Two: we hashed it, and only the hash goes on-chain — that is the privacy design. STEP 4 · Cold chain  [1:15]  (cum 6:10)

(Optional, if you prefer the live oracle: run  npx hardhat run oracle/index.js --network sepolia  in another terminal, then  $env:TEMP = "15.3"; node scripts/inject-excursion.js  — but the 20 s cycle makes it slower on stage.)
【中文】我们的预言机服务平时每个周期上报一次——三个原始样本，在链下过滤并求平均，一条签名读数上链。为了现场演示，我直接提交一条读数，这样就不用等周期；合约逻辑完全一样。我发一个尖峰——十五度，就像冰箱门被开着：（命令见上）一笔交易，三个事件：检测到越界、触发隔离、批次被隔离。监控合约调用了登记合约、改了批次状态——整个过程没有人参与。这三个事件都在这同一笔 Etherscan 交易里。（可选：如果你想用实时预言机，就在另一个终端跑 oracle 服务，再注入尖峰——但 20 秒的周期在台上会更慢。）

STEP 5 · Verify & recall  [0:50]  (cum 7:00)

  > npx hardhat run scripts/04-recall.js --network sepolia
Recalled on-chain — and the notifier finds every past holder from the events and notifies them. One transaction, instead of days. Everything you've just seen is on Etherscan right now — real, public, permanent. Zhenyu will now walk through the code.

STOP 1 · transferCustody  [0:45]  (cum 7:45)   Zhenyu
This function shows the state machine. Read it top to bottom: batch must be Active; sender must be the current holder; no self-transfer; receiver must have a role; expired batches cannot move. Then update, record history, emit the event. Every rule is a custom error, and every error has a test.
【中文】这个函数体现了状态机。从上往下读：批次必须是 Active 状态；发送者必须是当前持有人；不能转给自己；接收者必须有角色；过期批次不能转移。然后再更新、记录历史、发出事件。每一条规则都是一个自定义错误，每个错误都有对应的测试。

STOP 2 · reportReading  [0:50]  (cum 8:35)   Zhenyu
The oracle's gate. First, input checks: temperature must be realistic; timestamps must increase — no replays; no readings from the future. Then the logic: get this batch's range — default two to eight, can be changed per batch — count the excursion, and at the limit, the cross-contract call you saw in the demo. Note the order: state changes first, external call last — checks, effects, interactions.
【中文】这是预言机的入口关卡。首先是输入检查：温度必须合理；时间戳必须递增——不能重放；不能有来自未来的读数。然后是逻辑：取出这个批次的温度区间——默认 2 到 8，可以按批次修改——累计越界次数，达到上限时，就是你在演示里看到的那次跨合约调用。注意顺序：先改状态，最后才做外部调用——检查、生效、交互。

STOP 3 · oracle/index.js  [0:45]  (cum 9:20)   Zhenyu
(here this IS Zhenyu's own code — natural first person: "I wrote this service…")
The off-chain side. It finds batches by reading events — no config. Each cycle: sample, log raw data off-chain, drop bad samples, average, submit as the one authorised oracle account. When a batch is no longer Active, it stops. The chain never stores raw data — one clean reading per cycle.
【中文】链下这一侧。它通过读取事件来发现批次——不需要配置。每个周期：采样，把原始数据记到链下，丢掉坏样本，求平均，用那个唯一授权的预言机账户提交。当一个批次不再是 Active 状态时，就停止跟踪。链上从不存原始数据——每个周期只上报一条干净的读数。（这一段是 Zhenyu 自己写的代码，可以自然地用第一人称："这个服务是我写的……"）

STOP 4 · one test  [0:30]  (cum 9:50)   Zhenyu
One example of our tests. We set a three-strike rule: two bad readings — still Active, we assert that; third one — quarantined, asserted again. We test the business rule, not just the function. Thirty-one tests, all green.
【中文】举一个测试的例子。我们设了一个"三振"规则：两次坏读数——还是 Active，我们断言这一点；第三次——被隔离，再断言一次。我们测的是业务规则，不只是函数本身。三十一个测试，全绿。

Q&A quick answers (do NOT paste into slides)
-----------------------------------------------------------
• Trust the oracle? — Known weak point. One authorised account plus on-chain checks limit the damage. Production: multiple oracles, or sensors that sign their own data.
【中文】预言机可信吗？——这是已知的薄弱点。一个授权账户加上链上校验能限制损害。生产环境：多个预言机，或者让传感器自己签名数据。
• Why leave Fabric? — Same permission idea, now via contract roles. Public chain gives free verification and better tooling. Contracts would move to a consortium chain unchanged.
【中文】为什么放弃 Fabric？——权限理念不变，现在用合约角色实现。公有链带来免费的可核查性和更好的工具链。合约可以原封不动地迁到联盟链。
• GDPR/HIPAA? — No personal data on-chain, only hashes. Delete the off-chain file and the hash points to nothing — that is the right-to-erasure argument.
【中文】GDPR/HIPAA 合规？——链上没有任何个人数据，只有哈希。删掉链下文件，哈希就指向不了任何东西——这就是"被遗忘权"的论据。
• Gas? — Register 188k, transfer 113k, report 70k, recall 34k. Whole deployment plus demo: about 0.014 test ETH.
【中文】Gas 成本？——登记 18.8 万，转移 11.3 万，上报 7 万，召回 3.4 万。整个部署加演示：大约 0.014 个测试 ETH。
• Task 2 scalability targets? — Not met on a testnet, and we say so. Those numbers drive the production platform choice.
【中文】Task 2 的可扩展性指标？——在测试网上达不到，我们也如实说明。那些数字是用来指导生产环境平台选型的。
